# Android storage

Приложение для Android 12+. Android Studio устанавливается разработчиком;
глобальные Gradle и Kotlin не нужны. Wrapper хранится в проекте и загружает
зафиксированный Gradle при первом запуске. Автоматическая установка JDK и пакетов
Android SDK самим Gradle отключена.

| Компонент | Версия |
| --- | --- |
| Gradle Wrapper | 9.6.1 |
| Android Gradle Plugin | 9.3.3 |
| Kotlin Gradle Plugin | 2.4.21 |
| React Native | 0.88.1 |
| React | 19.3.1 |
| Compile SDK / Build Tools | 37.0 / 37.0.0 |
| Target SDK / минимальный Android | 36 / API 31 |
| NDK | 27.1.12297006 |

Gradle 9.6.1 поддерживает запуск на Java 25. При этом исходники React Native
Gradle Plugin задают `jvmToolchain(17)` для его компиляции. Поэтому JDK 17 нужно
установить параллельно: системную Java 25 менять не требуется. Приложение
генерирует Java/Kotlin bytecode с target 17. Включённый React Native Gradle Plugin
использует собственный Kotlin 2.2.0 независимо от Kotlin приложения. Gradle 9.6.1
содержит Kotlin 2.3.21, метаданные которого этот компилятор поддерживает.
Gradle 9.7.1 содержит уже несовместимый Kotlin 2.4. Версия 9.4.1 из шаблона React
Native подходит его плагину, но не нашему AGP 9.3.3, которому нужен Gradle >=9.5.

Для AGP 9 оставлены `android.builtInKotlin=false` и `android.newDsl=false`, как
в официальном шаблоне React Native 0.88.1. Удалять эти параметры до миграции
React Native Gradle Plugin и нативных зависимостей на новый DSL нельзя.

Установить JDK 17 и компоненты SDK через официальный Android CLI из Android SDK
Command-Line Tools. Android Studio для этого не нужна. `sdkmanager` в новых
версиях устарел; актуальная команда — `android sdk`.

```bash
sudo apt install openjdk-17-jdk
export ANDROID_HOME="$HOME/Android/Sdk"
"$ANDROID_HOME/cmdline-tools/latest/bin/android" --no-metrics --sdk="$ANDROID_HOME" sdk list --all
"$ANDROID_HOME/cmdline-tools/latest/bin/android" --no-metrics --sdk="$ANDROID_HOME" sdk install platform-tools platforms/android-37.0 build-tools/37.0.0 ndk/27.1.12297006 cmake/3.22.1
```

В индексе Google базовая платформа API 37 называется `platforms/android-37.0`,
а не `platforms/android-37`. Имя каталога Build Tools остаётся `37.0.0`.
В Gradle зафиксированы `compileSdk = 37` и `compileSdkMinor = 0`; это правило
применяется и к подключаемым Android-библиотекам после настройки их DSL.
Все Android-модули используют установленный Build Tools 37.0.0.

Лицензии прочитать и принять при установке. Если список пакетов не загружается,
установку не продолжать: запустить `android --verbose --no-metrics
--sdk="$ANDROID_HOME" sdk list --all` и проверить сетевую ошибку. Сообщение
`All SDK package licenses accepted` после ошибок загрузки манифестов само по себе
не подтверждает готовность SDK. TLS-проверку отключать не нужно.

`JAVA_HOME` может указывать на имеющийся JDK 25. `ANDROID_HOME` должен указывать
на установленный SDK, обычно `$HOME/Android/Sdk`. JDK 17 в стандартном каталоге
`/usr/lib/jvm` обнаруживается Gradle автоматически. Если он установлен иначе,
путь задаётся локально через настройки Gradle, без абсолютных путей в репозитории.

Из каталога `mobile` установить npm-зависимости и проверить TypeScript:

```bash
npm install
npm run typecheck
cd android
./gradlew --version
./gradlew javaToolchains
```

Node должен соответствовать React Native: `^22.13.0 || ^24.3.0 || >=26.0.0`.
Локальные зависимости и SDK не добавляются в Git. `package-lock.json`, созданный
успешным `npm install`, должен храниться в Git; далее используется `npm ci`.
Ошибку `407 Proxy Authentication Required` нужно устранить в настройках доступа
к npm, не отключая TLS-проверки и не добавляя учётные данные в репозиторий.

Текущий статус npm-уязвимостей и проверки приложения описаны в [SECURITY.md](SECURITY.md).
Перед применением `npm audit fix --force` нужно проверить предлагаемые версии:
сейчас npm предлагает откат React Native, а исправление picomatch ещё не выпущено.

В галерее кнопка «Загрузить с устройства» открывает встроенный выбор фото и видео:
альбомы, миниатюры, множественное выделение до 1000 файлов и страницы по 120 записей.
Android запрашивает доступ к медиатеке. При ограниченном доступе видны только
разрешённые фото и видео; кнопка «Изменить доступ» позволяет изменить выбор.
Сетка меняется сведением/разведением двух пальцев или кнопками «− / +» (2–6 колонок).
Оба экрана используют один нативный RecyclerView: во время жеста меняется масштаб,
после отпускания пальцев сетка перестраивается с анимацией и сохранением позиции.
Число колонок общее для галереи сервера и выбора устройства.
Для выделения диапазона удерживать файл и провести по соседним; у верхнего и
нижнего края работает автопрокрутка. Повторное выделение с уже отмеченного файла
снимает отметки диапазона. Обычный свайп одним пальцем прокручивает галерею.
Режим копирования/переноса и подтверждение закреплены под списком выбранных файлов.
В галерее доступны фильтры типа и даты; поиск по имени оставлен только для файлов.
Завершение фоновых передач не перезагружает открытую галерею: появляется кнопка
обновления, также можно потянуть список вниз. Пункты всплывающего меню прокручиваются
между закреплёнными заголовком и кнопкой закрытия; следующее действие запускается
после закрытия меню.
Облачные файлы, которых нет в локальном MediaStore, в этом списке не показываются.
В разделе «Файлы» используется системное окно выбора документов Android.

В серверной галерее «Выбрать» или удержание миниатюры включает множественное
выделение. Проведение после удержания отмечает диапазон. Закреплённая кнопка
«Действия» позволяет скопировать выбранное на устройство, вернуть на телефон,
переместить в корзину или поделиться файлами.
При возврате файл сначала сохраняется в медиатеку и проверяется по размеру и
SHA-256; только затем серверный оригинал попадает в корзину на 30 дней.
Незавершённый возврат можно повторить без повторного скачивания проверенной копии.
Копирование и подготовка отправки выполняются фоновой очередью.

Для отправки можно выбрать до 100 файлов. После подготовки открывается системное
меню Android; получателя выбирает пользователь. Файлы временно находятся в закрытом
каталоге приложения, без публикации в медиатеке. Подготовленная отправка доступна
24 часа; просроченный кэш очищается при следующей инициализации или подготовке
скачивания. В «Передаче» готовую отправку можно открыть кнопкой «Поделиться».

Подготовка данных и расчёт изменений нативной сетки выполняются вне UI-потока.
Запросы неизменившихся миниатюр используются повторно; во время быстрой инерционной
прокрутки новые загрузки откладываются до остановки списка.

Завершённые и отменённые передачи хранятся локально 7 дней с момента завершения.
Просроченные записи удаляются при чтении очереди приложением или фоновым обработчиком.
Очистка не удаляет файлы. Незавершённые задания, включая ошибки с возможностью
повтора, сохраняются. Существующая история без даты завершения сохраняется ещё
7 дней после обновления схемы локальной базы.

«Отменить все» в очереди останавливает незавершённые передачи текущего аккаунта
и сервера, включая задания на паузе и с ошибками. Готовые копии сохраняются;
незаконченные локальные скачивания очищаются. В выборе медиа отдельная кнопка
«Снять выделение» сбрасывает отмеченные файлы.

При переносе запрос постоянного разрешения на удаление ожидает возвращения из
настроек Android. Если постоянное разрешение не выдано, после проверки серверной
копии и оригинала открывается системное подтверждение удаления конкретного файла.
В фоне такое подтверждение не открывается: передача ожидает открытия приложения.

Для телефона по USB включить отладку, подтвердить компьютер и перенаправить порты:

```bash
adb devices
adb reverse tcp:8081 tcp:8081
adb reverse tcp:7000 tcp:7000
```

В одном терминале из `mobile` запустить `npm start` (Metro слушает только
`127.0.0.1`). `npm run android` использует уже запущенный Metro. В другом собрать и установить
debug-приложение с публичными параметрами своего сервера и бота:

```bash
cd mobile/android
./gradlew :app:installDebug -PSTORAGE_SERVER_URL=http://127.0.0.1:7000 -PSTORAGE_BOT_USERNAME=eva_persik_bot
```

В Android-эмуляторе вместо USB-перенаправления используется `http://10.0.2.2:7000`.
HTTP разрешён только в debug и только для локальных адресов. Для авторизации и
галереи должны работать API, основной Telegram-бот, MinIO и worker. Polling
позволяет проверять бота без публичного webhook.

Для release обязательны доверенный HTTPS `STORAGE_SERVER_URL` и
`STORAGE_BOT_USERNAME`; изменение сервера из приложения запрещено. Публичные
параметры передаются через `-P`, токены ботов в APK не встраиваются. Дополнительный
`.env` для мобильного приложения не создаётся. Подпись release пока не настроена.

Wrapper JAR проверен по опубликованному SHA-256. В `gradle-wrapper.properties`
зафиксирован SHA-256 дистрибутива: подменённый ZIP не должен запускаться.
Полная компиляция, проверка зависимостей и аудит установленного APK остаются
обязательными перед выпуском; изменение версий само по себе их не подтверждает.
