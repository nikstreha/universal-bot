# Android security review

Проверка продолжается. TypeScript, production JavaScript и debug APK успешно
собираются. Это не подтверждает безопасность приложения на устройстве:
перед использованием с личными файлами нужны проверки его поведения.

## npm: открытая уязвимость сборочных инструментов

На 17 ноября 2026 года `npm audit` сообщает о 28 high-узлах графа зависимостей,
связанных с одной исходной уязвимостью:
[GHSA-fc5q-39xc-vjpf / CVE-2026-112366](https://github.com/advisories/GHSA-fc5q-39xc-vjpf).

`picomatch <=4.0.7` может вызвать чрезмерную загрузку CPU при обработке специально
подготовленных повторяющихся extglob-шаблонов. Опубликованной исправленной версии
пока нет. Установлены `picomatch 2.3.2` и `4.0.7`; npm учитывает также пакеты,
зависящие от них через Metro, CLI, codegen, micromatch и tinyglobby.

Для текущего приложения собран production Android JS-bundle с `--dev false` и
проверены все 528 записей вложенной source map. `picomatch`, `micromatch`,
`tinyglobby`, `fdir`, `jest-util`, `jest-worker` и сборочные пакеты Metro в этот
bundle не входят. Это проверка фактического графа JS-модулей; анализ APK ещё
предстоит. Категория npm dependency/devDependency сама по себе не показывает,
какой код попадает в мобильное приложение.

Риск остаётся на машине сборки, где Node запускает уязвимый парсер. Шаблоны и
конфигурации сборки должны поступать из доверенного исходного кода. `npm start`
привязан к `127.0.0.1`; `npm run android` использует `--no-packager`, поэтому Metro
запускается отдельно контролируемой командой. Телефон подключается через
`adb reverse tcp:8081 tcp:8081`. Это сокращает сетевую поверхность, но не исправляет
сам парсер.

`npm audit fix --force` предлагает переход на React Native 0.83.10 — устаревшую
ветку вместо используемой 0.88.1. Рекомендация npm не считается подтверждением
безопасного и совместимого исправления. Обновление picomatch после публикации
исправления и повторный полный npm audit остаются необходимыми. Текущий отчёт
нельзя считать чистым.

## Выполненные проверки

- `npm run typecheck` проходит со strict и noUncheckedIndexedAccess. Унаследованные
  типы Jest заменены типами React/React Native; тестовые пакеты не добавлялись.
- Production JS-bundle собирается во временный каталог, без Android-компилятора.
- В проекте сохраняется `package-lock.json` для фиксации npm-зависимостей.
- Gradle Wrapper и его дистрибутив закреплены контрольными суммами SHA-256.
- `:app:assembleDebug` проходит на Gradle 9.6.1 с AGP 9.3.3, Kotlin приложения
  2.4.21 и React Native 0.88.1 для arm64-v8a и x86_64. Исправлены порядок
  регистрации Android DSL callbacks и обращение к Activity из native-модуля.
- На подключённом Android проверены копирование и возврат искусственного PNG:
  локальная копия прошла проверку, возврат завершился переносом серверной копии
  в корзину. Проверены подготовка файла и открытие системного Sharesheet без
  отправки получателю, а также выделение двух миниатюр со счётчиком «Выбрано 2».
  Личные файлы при этих операциях не изменялись. Проверочные локальные копии
  удалены; серверный PNG оставлен в корзине с обычным сроком очистки.

## Нативные изменения, ожидающие проверки на устройстве

- Release ограничен HTTPS-origin и Telegram-ботом, заданными при сборке.
- Ссылка входа проверяется до открытия Telegram; PKCE verifier остаётся в native.
- Токен сессии хранится через Android Keystore/AES-GCM с AAD, не выдаётся в React
  state, JS API или свойства изображений. API-запросы выполняет native-слой.
- Изображения и видео используют общий HTTP-клиент с проверкой origin и запретом
  перенаправлений. Дисковый кэш изображений отключён.
- Выход очищает сессию, кэш, временные скачивания и сохранённые URI-разрешения;
  задания и ответы проверяются по экземпляру сессии.
- Скачивания ограничены ожидаемым размером и проверяются по SHA-256 перед
  публикацией в MediaStore. Удаление оригиналов связано с проверенным заданием,
  текущей сессией и отдельным кодом системного запроса.
- При возврате с сервера проверяются скачанные байты, опубликованная локальная
  копия и актуальные метаданные сервера. Серверный файл переносится в корзину.
  URI незавершённой записи MediaStore сохраняется для восстановления после сбоя;
  очистка удаляет только принадлежащие приложению записи с `IS_PENDING=1`.
- Отправка использует FileProvider, ограниченный каталогом `files/shares/`.
  Получателю выдаётся временное право чтения выбранных файлов, без права записи.
  Токены и серверные URL в Intent не передаются. Физические имена кэша состоят
  из UUID; исходное имя используется только как отображаемое имя файла.
  Готовые группы действуют 24 часа; выход удаляет кэш отправки.
- Backup, перенос данных между устройствами, скриншоты и предпросмотр задач
  ограничены настройками Android.

На устройстве нужно проверить неверные TLS-сертификаты и чужие серверы,
перенаправления API/изображений/видео, выход во время передачи, переключение
аккаунтов, отзыв доступа, остановку фонового задания и отмену удаления оригинала.
Проверка отсутствия секретов в APK и release-подпись также ещё не завершены.
